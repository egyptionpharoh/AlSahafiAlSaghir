# دليل نشر «الصحفي الصغير» على الإنترنت

> هذا الدليل للتجهيز فقط. لم يُنشر التطبيق، ولم يُشترَ أي نطاق أو استضافة.

## ماذا يحتاج التطبيق من الاستضافة؟

| المتطلب | التفاصيل |
|---|---|
| بيئة التشغيل | Node.js **22.13 أو أحدث** (أو 24)، يعمل باستمرار (ليس «دوال سحابية» مؤقتة) |
| قاعدة البيانات | لا تحتاج خدمة منفصلة — ملف SQLite واحد داخل `DATA_DIR` |
| تخزين الصور | مجلد `uploads` داخل `DATA_DIR` |
| **قرص دائم** | **إلزامي.** يجب أن يكون `DATA_DIR` على قرص لا يُمسح عند إعادة التشغيل أو التحديث |
| HTTPS | إلزامي (الكوكي الآمن يتطلبه). كل المنصات المقترحة توفره مجانًا |
| الذاكرة | 512 ميغابايت كافية لمدرسة واحدة |
| نسخة واحدة | شغّل نسخة (instance) واحدة فقط من التطبيق — لا توسعة أفقية |

## لماذا لا يصلح Vercel؟
Vercel ممتاز لألعاب HTML الثابتة، لكنه يشغّل الكود كدوال مؤقتة بلا قرص دائم؛ لذلك تذكر Vercel نفسها أن SQLite لا يعمل عليها لأن التخزين المحلي مؤقت ولا يُشارك بين النسخ. لو نُشر التطبيق هناك ستضيع المقالات والصور.

## الخيار الموصى به (أ): خادم VPS صغير — أكثر تحكمًا وأقل كلفة على المدى الطويل
أي خادم لينكس (Ubuntu 24.04 مثلًا) من أي مزوّد.

1. ثبّت Node.js 22 LTS وخادم Caddy (من مواقعهما الرسمية).
2. انسخ المشروع إلى `/opt/alsahafi` (عبر SFTP أو git خاص).
3. أنشئ ملف الإعدادات:
   ```bash
   cd /opt/alsahafi
   cp .env.example .env
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # انسخ الناتج
   nano .env
   ```
   واضبط: `NODE_ENV=production`، `APP_SECRET=<الناتج>`، `BASE_URL=https://نطاقك`، `TRUST_PROXY=1`، `HOST=127.0.0.1`، `DATA_DIR=/opt/alsahafi/data`.
4. أنشئ حساب المسؤول: `node scripts/create-admin.js`
5. فعّل الخدمة الدائمة: اتبع التعليمات داخل `deploy/alsahafi.service`.
6. اربط النطاق بعنوان IP الخادم (سجل A)، ثم ضع `deploy/Caddyfile` (بعد تعديل النطاق) في `/etc/caddy/Caddyfile` وأعد تشغيل Caddy. يصدر شهادة HTTPS تلقائيًا.
7. جدولة نسخة احتياطية يومية (crontab):
   ```
   30 2 * * * cd /opt/alsahafi && /usr/bin/node scripts/backup.js >> backups/backup.log 2>&1
   ```
   وانسخ مجلد `backups` دوريًا إلى مكان خارج الخادم.

## الخيار (ب): Render (منصة جاهزة)
- **خدمة Web Service مدفوعة** (أصغر خطة مدفوعة: 7$ شهريًا وقت إعداد هذا الدليل) + **Persistent Disk** (0.25$ لكل غيغابايت شهريًا). الخطة المجانية **لا تدعم الأقراص الدائمة**.
- الإعداد: اربط المستودع (خاص)، اختر **Docker** (يستخدم `Dockerfile` الموجود)، أضف Disk بمسار تثبيت `/data` وحجم 1–5 GB.
- متغيرات البيئة: `APP_SECRET`، `BASE_URL`. (الباقي مضبوط في Dockerfile).
- إنشاء المسؤول: من تبويب **Shell** في لوحة Render نفّذ `node scripts/create-admin.js`.
- تنبيهات: مع القرص لا يتوفر نشر بلا توقف (يتوقف الموقع ثوانيَ عند كل تحديث)، ولا يمكن تشغيل أكثر من نسخة. يأخذ Render لقطة يومية للقرص تُحفظ 7 أيام — ومع ذلك احتفظ بنسخك الخاصة.

## الخيار (ج): Railway أو Fly.io
يعملان بنفس `Dockerfile` مع **Volume** مربوط على `/data`. تأكد بعد أول نشر أن البيانات تبقى بعد إعادة النشر: أنشئ مقالًا تجريبيًا، أعد النشر، وتحقق من بقائه (توجد شكاوى في منتدى Railway من ربط خاطئ للـ Volume يؤدي لفقدان البيانات).

## الاستضافات المشتركة (cPanel)
بعضها يدعم Node.js لكن غالبًا بإصدارات قديمة أو بلا تشغيل دائم. لا تعتمدها إلا إذا أكد المزوّد: Node.js 22.13+، تشغيل دائم، وكتابة دائمة على القرص.

## متغيرات البيئة في الإنتاج

| المتغير | القيمة | ملاحظة |
|---|---|---|
| `NODE_ENV` | `production` | يفعّل الكوكي الآمن وHSTS والتخزين المؤقت |
| `APP_SECRET` | 64 حرفًا عشوائيًا | إلزامي — التطبيق يرفض التشغيل بدونه |
| `BASE_URL` | `https://...` | لروابط المشاركة وبطاقات الدخول والغلاف الخلفي |
| `DATA_DIR` | مسار القرص الدائم | قاعدة البيانات والصور |
| `TRUST_PROXY` | `1` | عند وجود Caddy/Nginx/منصة أمام التطبيق |
| `PORT` | حسب المنصة | Render/Railway تضبطه تلقائيًا |
| `MAX_UPLOAD_MB` | `6` | بعد الضغط في المتصفح تكون الصور عادة أقل من 1 MB |

## قائمة التحقق بعد النشر
- [ ] `https://نطاقك/healthz` يعرض `ok`.
- [ ] الدخول بحساب المسؤول يعمل، والمتصفح يُظهر القفل (HTTPS).
- [ ] رفع صورة المدرسة من الإعدادات يظهر في الغلاف.
- [ ] أعد تشغيل التطبيق من لوحة الاستضافة — تأكد أن الصورة والمقالات ما زالت موجودة.
- [ ] جرّب حساب طالب من الهاتف: كتابة، رفع صورة من المعرض، إرسال.
- [ ] خذ نسخة احتياطية وتأكد أن مجلدها يحوي `app.db` و `uploads`.
